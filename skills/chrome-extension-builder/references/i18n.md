# WXT Internationalization (i18n)

Complete guide for internationalizing WXT extensions using `@wxt-dev/i18n` and custom runtime locale switching.

## Key Limitation: `@wxt-dev/i18n` Cannot Switch at Runtime

| Feature | `@wxt-dev/i18n` | Custom `useAppI18n` |
|---------|----------------|----------------------|
| Follows browser/OS language | ✅ | ❌ |
| Localizes manifest fields | ✅ | ❌ |
| Full type safety | ✅ | ✅ |
| Plural forms | ✅ | ✅ |
| **User can change language in-app** | ❌ | ✅ |
| **Persists language preference** | ❌ | ✅ |
| **Updates UI without reload** | ❌ | ✅ |

**Solution:** Use `@wxt-dev/i18n` for manifest only. Build custom `useAppI18n()` composable for UI localization.

## Setup

### 1. Install

```bash
pnpm i @wxt-dev/i18n
```

### 2. Configure `wxt.config.ts`

```typescript
export default defineConfig({
  modules: ['@wxt-dev/module-vue', '@wxt-dev/i18n/module'],
  manifest: {
    default_locale: 'en',
    // Use MSG_ tokens to localize manifest fields
    name: '__MSG_extName__',
    description: '__MSG_extDescription__',
  },
})
```

### 3. Create Locale Files

Create `<srcDir>/locales/<lang>.json` (JSON is recommended — no extra YAML parser required):

```json
// locales/en.json
{
  "extName": "My Extension",
  "extDescription": "A useful browser extension",

  "ok": "OK",
  "cancel": "Cancel",
  "save": "Save Settings",

  "settings": {
    "title": "Settings",
    "theme": "Theme",
    "notifications": "Enable Notifications"
  },

  "greeting": "Hello $1!",
  "savedCount": "Saved $1 items to $2",

  "itemCount": {
    "0": "No items",
    "1": "1 item",
    "n": "$1 items"
  }
}
```

```json
// locales/de.json
{
  "extName": "Meine Erweiterung",
  "extDescription": "Eine n\u00fctzliche Browser-Erweiterung",
  "ok": "OK",
  "cancel": "Abbrechen",
  "save": "Einstellungen speichern",
  "settings": {
    "title": "Einstellungen",
    "theme": "Design",
    "notifications": "Benachrichtigungen aktivieren"
  },
  "greeting": "Hallo $1!",
  "itemCount": {
    "0": "Keine Eintr\u00e4ge",
    "1": "1 Eintrag",
    "n": "$1 Eintr\u00e4ge"
  }
}
```

WXT generates TypeScript types from the locale files automatically when you run `wxt prepare` or any build command.

## Usage

The `i18n` object works in **all extension contexts** (background, content scripts, Vue SFCs). Always use the explicit import from `#i18n`:

```typescript
import { i18n } from '#i18n';

const title = i18n.t('settings.title')        // "Settings"
const greeting = i18n.t('greeting', ['Alice']) // "Hello Alice!"
const count = i18n.t('itemCount', 3)           // "3 items"
const count1 = i18n.t('itemCount', 1)          // "1 item"
const count0 = i18n.t('itemCount', 0)          // "No items"
```

The `#i18n` path is an alias generated by WXT when `@wxt-dev/i18n/module` is configured. It resolves to `.wxt/i18n/index.ts` and is TypeScript-safe.

## In Vue Components

Always add the explicit import at the top of each `<script setup>` block:

```vue
<!-- components/SettingsPanel.vue -->
<script setup lang="ts">
import { i18n } from '#i18n'; // required in every Vue SFC
const settingsSaved = ref(false)
</script>

<template>
  <UCard>
    <template #header>
      <h2>{{ i18n.t('settings.title') }}</h2>
    </template>

    <UFormField :label="i18n.t('settings.theme')">
      <!-- USelect v4: use :items not :options -->
      <USelect v-model="theme" :items="themeOptions" />
    </UFormField>

    <UFormField :label="i18n.t('settings.notifications')">
      <USwitch v-model="notifications" />
    </UFormField>

    <template #footer>
      <UButton @click="save">{{ i18n.t('save') }}</UButton>
    </template>
  </UCard>
</template>
```

## Supported File Formats

Locale files can be in any of these formats:

- `.json` (recommended — no extra parser dependency, works everywhere)
- `.yml` / `.yaml`
- `.jsonc`
- `.json5`
- `.toml`

## Messages File Reference

### Nested Keys

```json
{
  "dialogs": {
    "delete": {
      "title": "Delete Item?",
      "message": "This action cannot be undone.",
      "confirm": "Delete"
    }
  }
}
```

```typescript
i18n.t('dialogs.delete.title')   // "Delete Item?"
i18n.t('dialogs.delete.message') // "This action cannot be undone."
i18n.t('dialogs.delete.confirm') // "Delete"
```

### Substitutions (`$1`–`$9`)

```json
{
  "welcome": "Welcome back, $1!",
  "copied": "Copied $1 to $2"
}
```

```typescript
i18n.t('welcome', ['Alice'])            // "Welcome back, Alice!"
i18n.t('copied', ['link', 'clipboard']) // "Copied link to clipboard"
```

### Plural Forms

```json
{
  "files": {
    "0": "No files",
    "1": "1 file",
    "n": "$1 files"
  }
}
```

```typescript
i18n.t('files', 0) // "No files"
i18n.t('files', 1) // "1 file"
i18n.t('files', 5) // "5 files"
```

Custom `$1` substitution instead of count:

```json
{
  "selected": {
    "1": "$1 item selected",
    "n": "$1 items selected"
  }
}
```

```typescript
i18n.t('selected', 1, ['One'])  // "One item selected"
i18n.t('selected', 3, ['Three']) // "Three items selected"
```

## Localizing the Manifest

Reference any locale key in the manifest using `__MSG_keyName__` syntax:

```typescript
// wxt.config.ts
export default defineConfig({
  manifest: {
    default_locale: 'en',
    name: '__MSG_extName__',
    description: '__MSG_extDescription__',
    // Action tooltip, omnibox keyword, etc. also support __MSG_...__
    action: {
      default_title: '__MSG_actionTitle__',
    },
  },
})
```

## Adding a New Language

1. Create `locales/<lang>.json` with all keys from the default locale
2. Run `wxt prepare` to regenerate types
3. That's it — WXT picks it up automatically

Check which browser locales Chrome supports: [Supported Locales](https://developer.chrome.com/docs/extensions/reference/api/i18n#supported-locales)

## Vanilla `browser.i18n` Alternative

If you prefer zero dependencies, use the built-in browser API directly:

```typescript
// wxt.config.ts
export default defineConfig({
  manifest: { default_locale: 'en' },
})
```

Create `public/_locales/en/messages.json`:

```json
{
  "extName": { "message": "My Extension" },
  "greeting": { "message": "Hello $USER$!", "placeholders": { "USER": { "content": "$1" } } }
}
```

```typescript
browser.i18n.getMessage('extName')         // "My Extension"
browser.i18n.getMessage('greeting', 'Bob') // "Hello Bob!"
```

The vanilla API has no type safety, no plural forms, and requires verbose JSON — `@wxt-dev/i18n` is strongly recommended.

## Key Limitation: No Runtime Language Switching

`@wxt-dev/i18n` wraps `browser.i18n`, which reads the **browser's OS language** setting. This means:

- `i18n.t('key')` **always** returns the browser-language translation, regardless of what you store in `Settings.language`
- Users cannot switch language in-app — they must change their browser language
- A `language` field in your settings storage has **no effect** on `@wxt-dev/i18n` calls

If you need a runtime language switcher in the UI, implement a custom reactive composable. See **Runtime Locale Switching** below.

## Runtime Locale Switching

When users need to pick their language inside the extension (instead of changing the browser language), implement a reactive locale composable that imports the JSON locale files directly.

### How It Works

```
@wxt-dev/i18n (browser.i18n)      Custom useAppI18n composable
─────────────────────────────      ──────────────────────────────
Uses browser OS language           Reads Settings.language from storage
Always reads browser locale        Reactive — updates all bindings on change
Can localize manifest/CSS          Vue-only (UI strings)
Cannot switch at runtime           setLocale() switches instantly, no reload
```

Use both together: `@wxt-dev/i18n` for manifest/CSS localisation, a custom composable for all Vue UI strings.

### Create the Composable

```typescript
// src/composables/useAppI18n.ts
import { ref, computed, onMounted } from 'vue';
import { settingsStorage } from '../utils/storage'; // your WXT storage item
import enMessages from '../locales/en.json';
import deMessages from '../locales/de.json';

type Messages = Record<string, string | Record<string, string>>
export type LocaleCode = 'en' | 'de';

const MESSAGES: Record<LocaleCode, Messages> = {
  en: enMessages as Messages,
  de: deMessages as Messages,
}

export const AVAILABLE_LOCALES: { code: LocaleCode; name: string }[] = [
  { code: 'en', name: 'English' },
  { code: 'de', name: 'Deutsch' },
]

// Module-level singleton — one locale ref per entrypoint JS context.
// All components in the same page share it so setLocale() updates everything.
const locale = ref<LocaleCode>('en')
let storageWatcherAttached = false

function substituteArgs(template: string, args: (string | number)[]): string {
  return template.replace(/\$(\d+)/g, (_, i) => String(args[Number(i) - 1] ?? ''))
}

function translate(msgs: Messages, key: string, args: (string | number)[]): string {
  const entry = msgs[key]
  if (entry === undefined) return key
  if (typeof entry === 'object') {
    // Plural: { "1": "1 item", "n": "$1 items" }
    const count = typeof args[0] === 'number' ? args[0] : 0
    const template = count === 1 ? entry['1'] : entry['n']
    return substituteArgs(template ?? key, args)
  }
  return substituteArgs(entry, args)
}

export function useAppI18n() {
  onMounted(async () => {
    const settings = await settingsStorage.getValue()
    locale.value = (settings.language as LocaleCode) ?? 'en';

    // Attach storage watcher once per JS context — keeps pages in sync
    if (!storageWatcherAttached) {
      storageWatcherAttached = true
      settingsStorage.watch((s) => {
        if (s?.language) locale.value = s.language as LocaleCode
      })
    }
  })

  const messages = computed(() => MESSAGES[locale.value] ?? MESSAGES.en)

  function t(key: string, ...args: (string | number)[]): string {
    return translate(messages.value, key, args)
  }

  /** Updates locale immediately (reactive) and persists to storage. */
  async function setLocale(lang: LocaleCode): Promise<void> {
    locale.value = lang
    const settings = await settingsStorage.getValue()
    await settingsStorage.setValue({ ...settings, language: lang })
  }

  return { t, locale, setLocale, availableLocales: AVAILABLE_LOCALES }
}
```

**Critical architectural points:**
- The `locale` ref is **module-level** — shared across all components in one page. Calling `setLocale()` in one component instantly updates every other component using the composable.
- Each entrypoint (popup, options, sidepanel) is a **separate JS context** — they do NOT share the module-level ref. Changes propagate across contexts via `settingsStorage.watch()`.
- The `storageWatcherAttached` guard prevents duplicate watchers when multiple components call `useAppI18n()`.

### Key Argument Difference from `@wxt-dev/i18n`

```typescript
// @wxt-dev/i18n — array for named substitutions
i18n.t('greeting', ['Alice'])      // "Hello Alice!"
i18n.t('items', 5, ['5'])          // count + substitution array

// useAppI18n — variadic, count IS the $1 substitution
t('greeting', 'Alice')             // "Hello Alice!"
t('itemCount', 5)                  // "5 items" — count is also $1
```

### Usage in Vue Components

Replace `import { i18n } from '#i18n'` with the composable in every Vue file:

```vue
<script setup lang="ts">
// Explicit import required — WXT does not auto-import user composables
import { useAppI18n } from '../../composables/useAppI18n';
const { t } = useAppI18n()
</script>

<template>
  <UButton>{{ t('save') }}</UButton>
  <p>{{ t('itemCount', store.items.length) }}</p>
</template>
```

> **Note**: Unlike WXT auto-imported Vue globals (`ref`, `computed`, etc.), `useAppI18n` **requires an explicit import** because it lives in `src/composables/` and WXT does NOT auto-import user-defined composables in that directory.

### Locale Switching UI with ULocaleSelect

`ULocaleSelect` from Nuxt UI shows **nothing** without `:locales` and `v-model`. The `locales` prop must be `{ code: string, name: string }[]`:

```vue
<ULocaleSelect
  :model-value="locale"
  :locales="availableLocales"
  @update:model-value="(v) => setLocale(v as 'en' | 'de')"
/>
```

`availableLocales` from `useAppI18n()` is already `{ code, name }[]`. See [vue-integration.md](vue-integration.md) for more.

### JSON Locale File Format

The custom composable handles the same simplified JSON format that `@wxt-dev/i18n` uses:

```json
{
  "save": "Save",
  "greeting": "Hello $1!",
  "itemCount": {
    "1": "1 item",
    "n": "$1 items"
  }
}
```

One set of locale files serves both `@wxt-dev/i18n` (manifest/CSS) and `useAppI18n` (Vue UI).
